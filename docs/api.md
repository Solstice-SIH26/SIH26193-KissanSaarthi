## Tokens

| Method | Path                   | Description                                                  |
| ------ | ---------------------- | ------------------------------------------------------------ |
| POST   | `/tokens`              | Farmer submits a new procurement request (status: `pending`) |
| GET    | `/tokens/{id}`         | Get a single token/request's current status                  |
| PATCH  | `/tokens/{id}/approve` | Staff approves a pending request (capacity-checked)          |
| PATCH  | `/tokens/{id}/reject`  | Staff rejects a pending request                              |
| PATCH  | `/tokens/{id}/cancel`  | Cancel an approved token                                     |
| PATCH  | `/tokens/{id}/status`  | Update status between `waiting → called → completed`         |

## Centres

| Method | Path                  | Description                                                         |
| ------ | --------------------- | ------------------------------------------------------------------- |
| GET    | `/centers`            | List all active procurement centres (optional `?crop_type=` filter) |
| GET    | `/centers/{id}`       | Get a single centre's details                                       |
| GET    | `/centers/{id}/queue` | Get a centre's token queue (optional `?status=` filter)             |
| POST   | `/centers`            | (Admin) Create a new centre                                         |
| PATCH  | `/centers/{id}`       | (Admin) Update centre details, price, or capacity                   |

## Voice / Vapi

| Method | Path             | Description                                                                    |
| ------ | ---------------- | ------------------------------------------------------------------------------ |
| GET    | `/voice/context` | Returns caller identification and active token context for the voice assistant |

## Authentication

Authentication is handled via Supabase Auth (email or phone + password).
The `profiles` table stores each user's `role` (`farmer` / `procurement` / `admin`),
which drives role-based access on both frontend and backend.
